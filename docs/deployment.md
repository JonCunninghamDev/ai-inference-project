# Air-Gapped RAG Deployment Guide\n\nThis guide provides step-by-step instructions for deploying the Air-Gapped RAG system across all environments.\n\n## Prerequisites\n\n### Required Tools\n- **Python 3.12+** with uv package manager\n- **Node.js 20+** for AWS CDK\n- **AWS CLI v2** configured with appropriate credentials\n- **Docker** (for local vLLM testing)\n- **Git** for version control\n\n### AWS Requirements\n- AWS Account with appropriate permissions\n- CDK bootstrapped in target region\n- VPC quotas sufficient for isolated subnets\n- Route 53 (optional, for custom domains)\n\n### Network Requirements\n- Static public IP for VPN connection\n- Firewall rules allowing UDP 500/4500 for IPsec\n- Local strongSwan installation capability\n\n## Quick Start\n\n### 1. Clone and Setup\n```bash\n# Clone repository\ngit clone <repository-url>\ncd ai-inference\n\n# Install dependencies\nuv sync --extra dev\n\n# Activate virtual environment\nsource .venv/bin/activate\n```\n\n### 2. Configure Environment\n```bash\n# Copy and customize environment files\ncp config/dev.env.example config/dev.env\n\n# Edit configuration\nvim config/dev.env\n```\n\n### 3. Deploy Infrastructure\n```bash\n# Deploy to development\n./scripts/deploy.sh dev deploy\n\n# Check deployment status\n./scripts/deploy.sh dev status\n```\n\n### 4. Configure VPN (requires root)\n```bash\n# Setup VPN connection\nsudo ./scripts/setup_vpn.sh dev\n\n# Update VPN configuration with AWS outputs\nsudo ./scripts/update_vpn_config.sh dev\n```\n\n### 5. Start Services\n```bash\n# Install and start worker service\nsudo systemctl enable rag-worker\nsudo systemctl start rag-worker\n\n# Start health monitoring\nsudo systemctl enable rag-monitor\nsudo systemctl start rag-monitor\n```\n\n## Detailed Deployment Steps\n\n### Environment Configuration\n\nEach environment requires specific configuration in `config/{env}.env`:\n\n#### Development Environment\n```bash\n# AWS Configuration\nAWS_REGION=us-east-1\nAWS_ACCOUNT_ID=your-account-id\n\n# Network Configuration\nHOME_IP=your-public-ip\nVPC_CIDR=10.0.0.0/16\nVPN_TUNNEL_CIDR=169.254.10.0/30\n\n# Queue Configuration\nQUEUE_NAME=ai-inference-queue-Dev\nDLQ_NAME=ai-inference-dlq-Dev\n\n# vLLM Configuration\nVLLM_URL=http://localhost:8000/v1\nVLLM_MODEL=llama-3.1-8b\n```\n\n#### Production Environment\n```bash\n# AWS Configuration\nAWS_REGION=us-east-1\nAWS_ACCOUNT_ID=your-account-id\n\n# Network Configuration (different IP and CIDR)\nHOME_IP=your-prod-gateway-ip\nVPC_CIDR=10.2.0.0/16\nVPN_TUNNEL_CIDR=169.254.12.0/30\n\n# Enhanced timeouts for production\nQUEUE_VISIBILITY_TIMEOUT=600\nWORKER_POLL_INTERVAL=10\nWORKER_MAX_RETRIES=5\n```\n\n### Infrastructure Deployment\n\n#### Using Deployment Script\n```bash\n# Deploy with validation\n./scripts/deploy.sh prod deploy\n\n# Update existing deployment\n./scripts/deploy.sh prod update\n\n# Check status\n./scripts/deploy.sh prod status\n\n# Destroy (careful!)\n./scripts/deploy.sh prod destroy\n```\n\n#### Manual CDK Deployment\n```bash\n# Bootstrap CDK (first time only)\ncdk bootstrap aws://ACCOUNT-ID/REGION\n\n# Deploy specific stack\ncdk deploy AirGappedRag-Prod --require-approval never\n\n# View differences\ncdk diff AirGappedRag-Prod\n\n# Destroy stack\ncdk destroy AirGappedRag-Prod\n```\n\n### VPN Configuration\n\n#### Automated Setup\n```bash\n# Run VPN setup script (requires root)\nsudo ./scripts/setup_vpn.sh prod\n\n# Update with AWS VPN gateway details\nsudo ./scripts/update_vpn_config.sh prod\n\n# Test VPN connectivity\nsudo ipsec status\nping 10.2.0.1  # Test VPC connectivity\n```\n\n#### Manual Configuration\n\n1. **Install strongSwan**\n   ```bash\n   # Ubuntu/Debian\n   sudo apt-get install strongswan strongswan-pki\n   \n   # RHEL/CentOS\n   sudo yum install strongswan\n   ```\n\n2. **Configure ipsec.conf**\n   ```bash\n   sudo vim /etc/ipsec.conf\n   ```\n   \n   Add configuration:\n   ```\n   config setup\n       charondebug=\"ike 1, knl 1, cfg 0\"\n       uniqueids=no\n   \n   conn aws-prod\n       auto=start\n       left=%defaultroute\n       leftid=YOUR_PUBLIC_IP\n       leftsubnet=0.0.0.0/0\n       right=AWS_VPN_GATEWAY_IP\n       rightsubnet=10.2.0.0/16\n       ike=aes256-sha1-modp1024!\n       esp=aes256-sha1!\n       keyingtries=0\n       ikelifetime=1h\n       lifetime=8h\n       dpddelay=30\n       dpdtimeout=120\n       dpdaction=restart\n       authby=secret\n   ```\n\n3. **Configure ipsec.secrets**\n   ```bash\n   sudo vim /etc/ipsec.secrets\n   ```\n   \n   Add pre-shared key:\n   ```\n   YOUR_PUBLIC_IP AWS_VPN_GATEWAY_IP : PSK \"your-pre-shared-key\"\n   ```\n\n4. **Start strongSwan**\n   ```bash\n   sudo systemctl enable strongswan\n   sudo systemctl start strongswan\n   ```\n\n### Worker Service Deployment\n\n#### Service Installation\n```bash\n# Create service user\nsudo useradd -r -s /bin/false -d /opt/ai-inference rag-worker\n\n# Create directories\nsudo mkdir -p /opt/ai-inference/{src,config,logs}\n\n# Copy application files\nsudo cp -r src/* /opt/ai-inference/src/\nsudo cp config/prod.env /opt/ai-inference/config/\n\n# Install systemd services\nsudo cp systemd/rag-worker.service /etc/systemd/system/\nsudo cp systemd/rag-monitor.service /etc/systemd/system/\n\n# Set permissions\nsudo chown -R rag-worker:rag-worker /opt/ai-inference\nsudo chmod +x /opt/ai-inference/src/worker.py\n```\n\n#### Service Management\n```bash\n# Enable services\nsudo systemctl daemon-reload\nsudo systemctl enable rag-worker rag-monitor\n\n# Start services\nsudo systemctl start rag-worker\nsudo systemctl start rag-monitor\n\n# Check status\nsudo systemctl status rag-worker\nsudo journalctl -u rag-worker -f\n\n# Restart services\nsudo systemctl restart rag-worker\n\n# Stop services\nsudo systemctl stop rag-worker rag-monitor\n```\n\n### vLLM Server Setup\n\n#### Local Installation\n```bash\n# Install vLLM\npip install vllm\n\n# Download model (example)\nhuggingface-cli download meta-llama/Llama-3.1-8B-Instruct\n\n# Start vLLM server\nvllm serve meta-llama/Llama-3.1-8B-Instruct \\\n    --host 0.0.0.0 \\\n    --port 8000 \\\n    --api-key local-airgap\n```\n\n#### Docker Deployment\n```bash\n# Create docker-compose.yml\ncat > docker-compose.yml << EOF\nversion: '3.8'\nservices:\n  vllm:\n    image: vllm/vllm-openai:latest\n    ports:\n      - \"8000:8000\"\n    volumes:\n      - ./models:/models\n    command: >\n      --model /models/Llama-3.1-8B-Instruct\n      --host 0.0.0.0\n      --port 8000\n      --api-key local-airgap\n    deploy:\n      resources:\n        reservations:\n          devices:\n            - driver: nvidia\n              count: 1\n              capabilities: [gpu]\nEOF\n\n# Start vLLM\ndocker-compose up -d\n```\n\n## Monitoring and Maintenance\n\n### CloudWatch Dashboards\n\nAccess monitoring dashboards:\n- **Development**: https://console.aws.amazon.com/cloudwatch/home#dashboards:name=AirGappedRAG-Dev\n- **Staging**: https://console.aws.amazon.com/cloudwatch/home#dashboards:name=AirGappedRAG-Staging\n- **Production**: https://console.aws.amazon.com/cloudwatch/home#dashboards:name=AirGappedRAG-Prod\n\n### Health Monitoring\n\n```bash\n# Check system health\npython scripts/health_monitor.py prod --once\n\n# Continuous monitoring\npython scripts/health_monitor.py prod\n\n# View health metrics\naws cloudwatch get-metric-statistics \\\n    --namespace AirGappedRAG \\\n    --metric-name WorkerHealthy \\\n    --dimensions Name=Environment,Value=prod \\\n    --start-time 2024-01-01T00:00:00Z \\\n    --end-time 2024-01-01T23:59:59Z \\\n    --period 300 \\\n    --statistics Average\n```\n\n### Log Management\n\n```bash\n# View worker logs\nsudo journalctl -u rag-worker -f\n\n# View CloudWatch logs\naws logs tail /ai-inference/worker-Prod --follow\n\n# Search for errors\naws logs filter-log-events \\\n    --log-group-name /ai-inference/worker-Prod \\\n    --filter-pattern \"ERROR\"\n```\n\n### Backup and Recovery\n\n#### Configuration Backup\n```bash\n# Backup SSM parameters\naws ssm get-parameters-by-path \\\n    --path \"/ai-inference/config/Prod\" \\\n    --recursive > ssm-backup-prod.json\n\n# Backup SQS messages (if needed)\naws sqs receive-message \\\n    --queue-url https://sqs.region.amazonaws.com/account/queue-name \\\n    --max-number-of-messages 10\n```\n\n#### Disaster Recovery\n```bash\n# Restore from backup\n./scripts/deploy.sh prod deploy\n\n# Restore SSM parameters\naws ssm put-parameter \\\n    --name \"/ai-inference/config/Prod/enable-processing\" \\\n    --value \"true\" \\\n    --type String \\\n    --overwrite\n\n# Restart services\nsudo systemctl restart rag-worker rag-monitor\n```\n\n## Troubleshooting\n\n### Common Issues\n\n#### VPN Connection Issues\n```bash\n# Check VPN status\nsudo ipsec status\nsudo ipsec statusall\n\n# Restart VPN\nsudo ipsec restart\n\n# Check logs\nsudo journalctl -u strongswan -f\n\n# Test connectivity\nping 10.2.0.1  # VPC gateway\nnslookup sqs.us-east-1.amazonaws.com\n```\n\n#### Worker Service Issues\n```bash\n# Check service status\nsudo systemctl status rag-worker\n\n# View detailed logs\nsudo journalctl -u rag-worker --since \"1 hour ago\"\n\n# Check configuration\npython -c \"from src.config import get_config; print(get_config('prod'))\"\n\n# Test AWS connectivity\naws sts get-caller-identity\naws sqs get-queue-attributes --queue-url QUEUE_URL\n```\n\n#### vLLM Server Issues\n```bash\n# Check vLLM status\ncurl http://localhost:8000/v1/models\n\n# View vLLM logs\ndocker logs vllm-container\n\n# Restart vLLM\ndocker-compose restart vllm\n```\n\n### Performance Tuning\n\n#### Worker Optimization\n```bash\n# Adjust worker settings in config\nWORKER_POLL_INTERVAL=5  # Faster polling\nWORKER_MAX_RETRIES=10   # More retries\nQUEUE_VISIBILITY_TIMEOUT=900  # Longer processing time\n```\n\n#### vLLM Optimization\n```bash\n# GPU memory optimization\nvllm serve model \\\n    --gpu-memory-utilization 0.9 \\\n    --max-model-len 4096 \\\n    --tensor-parallel-size 2\n```\n\n## Security Considerations\n\n### Network Security\n- VPN tunnels use AES-256 encryption\n- All traffic routed through private VPC endpoints\n- No direct internet access from worker environment\n- Security groups restrict access to necessary ports only\n\n### Data Security\n- SQS messages encrypted with KMS\n- CloudWatch logs encrypted at rest\n- VPN pre-shared keys stored in SSM SecureString\n- Worker runs with minimal privileges\n\n### Access Control\n- IAM roles follow least privilege principle\n- Multi-factor authentication required for production\n- Separate AWS accounts for each environment\n- Regular key rotation (90 days for dev, 30 days for prod)\n\n## Compliance and Auditing\n\n### Audit Logging\n- All API calls logged via CloudTrail\n- Worker activities logged to CloudWatch\n- VPN connection events monitored\n- Failed authentication attempts tracked\n\n### Compliance Reports\n```bash\n# Generate compliance report\naws cloudtrail
