# Air-Gapped RAG Troubleshooting Runbook\n\nThis runbook provides step-by-step troubleshooting procedures for common issues in the Air-Gapped RAG system.\n\n## 🚨 Emergency Procedures\n\n### System Down - Complete Outage\n\n**Symptoms**: No message processing, all health checks failing\n\n**Immediate Actions**:\n1. Check CloudWatch dashboard for system overview\n2. Verify VPN tunnel status\n3. Check worker service status\n4. Validate AWS connectivity\n\n```bash\n# Quick health check\npython scripts/health_monitor.py prod --once\n\n# Check critical services\nsudo systemctl status rag-worker\nsudo ipsec status\naws sts get-caller-identity\n```\n\n**Escalation**: If not resolved in 15 minutes, escalate to on-call engineer\n\n### High Error Rate Alert\n\n**Symptoms**: Error rate > 25%, messages moving to DLQ\n\n**Immediate Actions**:\n1. Check recent error logs\n2. Verify vLLM server status\n3. Check queue depth and processing rate\n4. Review recent deployments\n\n```bash\n# Check recent errors\naws logs filter-log-events \\\n    --log-group-name /ai-inference/worker-Prod \\\n    --filter-pattern \"ERROR\" \\\n    --start-time $(date -d '1 hour ago' +%s)000\n\n# Check vLLM connectivity\ncurl -f http://localhost:8000/v1/models || echo \"vLLM unreachable\"\n```\n\n### Security Incident\n\n**Symptoms**: Unauthorized access attempts, unusual traffic patterns\n\n**Immediate Actions**:\n1. Enable kill switch to stop processing\n2. Review CloudTrail logs for suspicious activity\n3. Check VPN connection logs\n4. Notify security team\n\n```bash\n# Emergency stop\naws ssm put-parameter \\\n    --name \"/ai-inference/config/Prod/enable-processing\" \\\n    --value \"false\" \\\n    --type String \\\n    --overwrite\n\n# Check recent API calls\naws cloudtrail lookup-events \\\n    --lookup-attributes AttributeKey=EventName,AttributeValue=AssumeRole \\\n    --start-time $(date -d '1 hour ago' --iso-8601)\n```\n\n## 🔧 Component-Specific Troubleshooting\n\n### VPN Connection Issues\n\n#### Problem: VPN Tunnel Down\n\n**Symptoms**:\n- Cannot reach AWS services\n- VPN status shows \"down\" or \"connecting\"\n- Timeout errors when accessing SQS/SSM\n\n**Diagnosis**:\n```bash\n# Check VPN status\nsudo ipsec status\nsudo ipsec statusall\n\n# Check strongSwan logs\nsudo journalctl -u strongswan --since \"1 hour ago\"\n\n# Test network connectivity\nping -c 3 8.8.8.8  # Internet connectivity\nping -c 3 10.2.0.1  # VPC gateway (adjust for your VPC)\n```\n\n**Resolution Steps**:\n1. **Restart VPN connection**:\n   ```bash\n   sudo ipsec restart\n   sleep 10\n   sudo ipsec status\n   ```\n\n2. **Check configuration**:\n   ```bash\n   sudo ipsec verify\n   sudo cat /etc/ipsec.conf\n   sudo cat /etc/ipsec.secrets\n   ```\n\n3. **Verify AWS VPN Gateway status**:\n   ```bash\n   aws ec2 describe-vpn-connections \\\n       --vpn-connection-ids vpn-xxxxxxxxx\n   ```\n\n4. **Check firewall rules**:\n   ```bash\n   sudo iptables -L -n | grep -E \"500|4500\"\n   sudo ufw status  # If using UFW\n   ```\n\n5. **Regenerate VPN configuration** (if needed):\n   ```bash\n   sudo ./scripts/setup_vpn.sh prod\n   sudo ./scripts/update_vpn_config.sh prod\n   ```\n\n#### Problem: Intermittent VPN Disconnections\n\n**Symptoms**:\n- Periodic connection drops\n- \"DPD timeout\" in logs\n- Sporadic AWS service timeouts\n\n**Resolution**:\n1. **Adjust DPD settings** in `/etc/ipsec.conf`:\n   ```\n   dpddelay=10\n   dpdtimeout=60\n   dpdaction=restart\n   ```\n\n2. **Check network stability**:\n   ```bash\n   ping -c 100 AWS_VPN_GATEWAY_IP\n   mtr --report --report-cycles 100 AWS_VPN_GATEWAY_IP\n   ```\n\n3. **Monitor for pattern**:\n   ```bash\n   sudo journalctl -u strongswan -f | grep -E \"DPD|timeout|restart\"\n   ```\n\n### Worker Service Issues\n\n#### Problem: Worker Not Processing Messages\n\n**Symptoms**:\n- Messages accumulating in SQS queue\n- Worker service running but no activity\n- No recent log entries\n\n**Diagnosis**:\n```bash\n# Check service status\nsudo systemctl status rag-worker\n\n# Check recent logs\nsudo journalctl -u rag-worker --since \"30 minutes ago\"\n\n# Check kill switch\naws ssm get-parameter \\\n    --name \"/ai-inference/config/Prod/enable-processing\"\n\n# Check queue attributes\naws sqs get-queue-attributes \\\n    --queue-url \"$(aws ssm get-parameter --name '/ai-inference/config/Prod/queue-url' --query 'Parameter.Value' --output text)\" \\\n    --attribute-names All\n```\n\n**Resolution Steps**:\n1. **Check kill switch**:\n   ```bash\n   # Enable processing if disabled\n   aws ssm put-parameter \\\n       --name \"/ai-inference/config/Prod/enable-processing\" \\\n       --value \"true\" \\\n       --type String \\\n       --overwrite\n   ```\n\n2. **Restart worker service**:\n   ```bash\n   sudo systemctl restart rag-worker\n   sleep 5\n   sudo systemctl status rag-worker\n   ```\n\n3. **Check configuration**:\n   ```bash\n   # Validate config\n   cd /opt/ai-inference\n   source .venv/bin/activate\n   python -c \"from src.config import get_config; print(get_config('prod'))\"\n   ```\n\n4. **Test AWS connectivity**:\n   ```bash\n   # Test SQS access\n   aws sqs receive-message \\\n       --queue-url \"QUEUE_URL\" \\\n       --max-number-of-messages 1\n   \n   # Test SSM access\n   aws ssm get-parameter \\\n       --name \"/ai-inference/config/Prod/enable-processing\"\n   ```\n\n5. **Check worker permissions**:\n   ```bash\n   # Verify IAM role\n   aws sts get-caller-identity\n   \n   # Test queue permissions\n   aws sqs get-queue-attributes \\\n       --queue-url \"QUEUE_URL\" \\\n       --attribute-names Policy\n   ```\n\n#### Problem: Worker Crashing/Restarting\n\n**Symptoms**:\n- Frequent service restarts\n- \"Failed\" status in systemctl\n- Core dumps or Python tracebacks\n\n**Diagnosis**:\n```bash\n# Check crash logs\nsudo journalctl -u rag-worker --since \"1 hour ago\" | grep -E \"ERROR|CRITICAL|Traceback\"\n\n# Check system resources\nfree -h\ndf -h\ntop -p $(pgrep -f rag-worker)\n\n# Check for core dumps\nsudo coredumpctl list\n```\n\n**Resolution Steps**:\n1. **Check resource limits**:\n   ```bash\n   # Check systemd limits\n   sudo systemctl show rag-worker | grep -E \"Memory|CPU\"\n   \n   # Adjust if needed in service file\n   sudo vim /etc/systemd/system/rag-worker.service\n   sudo systemctl daemon-reload\n   ```\n\n2. **Check Python environment**:\n   ```bash\n   # Verify virtual environment\n   cd /opt/ai-inference\n   source .venv/bin/activate\n   python --version\n   pip list | grep -E \"boto3|openai|pydantic\"\n   ```\n\n3. **Run worker manually for debugging**:\n   ```bash\n   sudo -u rag-worker bash\n   cd /opt/ai-inference\n   source .venv/bin/activate\n   ENVIRONMENT=prod python src/worker.py\n   ```\n\n### vLLM Server Issues\n\n#### Problem: vLLM Server Unreachable\n\n**Symptoms**:\n- Connection refused on port 8000\n- Timeout errors in worker logs\n- \"VLLMAccessible\" metric showing 0\n\n**Diagnosis**:\n```bash\n# Check vLLM server status\ncurl -f http://localhost:8000/v1/models\nnetstat -tlnp | grep 8000\n\n# Check Docker container (if using Docker)\ndocker ps | grep vllm\ndocker logs vllm-container --tail 50\n\n# Check process (if running directly)\nps aux | grep vllm\n```\n\n**Resolution Steps**:\n1. **Restart vLLM server**:\n   ```bash\n   # Docker deployment\n   docker-compose restart vllm\n   \n   # Direct installation\n   pkill -f vllm\n   vllm serve meta-llama/Llama-3.1-8B-Instruct \\\n       --host 0.0.0.0 \\\n       --port 8000 \\\n       --api-key local-airgap &\n   ```\n\n2. **Check GPU availability** (if using GPU):\n   ```bash\n   nvidia-smi\n   docker run --rm --gpus all nvidia/cuda:11.8-base-ubuntu20.04 nvidia-smi\n   ```\n\n3. **Check disk space and memory**:\n   ```bash\n   df -h /path/to/models\n   free -h\n   ```\n\n4. **Verify model files**:\n   ```bash\n   ls -la /path/to/models/\n   du -sh /path/to/models/*\n   ```\n\n#### Problem: vLLM High Response Times\n\n**Symptoms**:\n- Slow inference responses (>30 seconds)\n- High \"VLLMResponseTime\" metrics\n- Worker timeouts\n\n**Resolution Steps**:\n1. **Check GPU utilization**:\n   ```bash\n   nvidia-smi -l 1\n   ```\n\n2. **Optimize vLLM parameters**:\n   ```bash\n   # Restart with optimized settings\n   vllm serve model \\\n       --gpu-memory-utilization 0.9 \\\n       --max-model-len 2048 \\\n       --tensor-parallel-size 2 \\\n       --max-num-batched-tokens 4096\n   ```\n\n3. **Monitor resource usage**:\n   ```bash\n   htop\n   iotop\n   ```\n\n### AWS Service Issues\n\n#### Problem: SQS Queue Issues\n\n**Symptoms**:\n- Messages not being delivered\n- High message age\n- DLQ receiving messages\n\n**Diagnosis**:\n```bash\n# Check queue metrics\naws sqs get-queue-attributes \\\n    --queue-url \"QUEUE_URL\" \\\n    --attribute-names All\n\n# Check DLQ\naws sqs get-queue-attributes \\\n    --queue-url \"DLQ_URL\" \\\n    --attribute-names All\n\n# Sample messages from DLQ\naws sqs receive-message \\\n    --queue-url \"DLQ_URL\" \\\n    --max-number-of-messages 5\n```\n\n**Resolution Steps**:\n1. **Purge DLQ and retry**:\n   ```bash\n   # Move messages back to main queue (if appropriate)\n   aws sqs redrive-policy \\\n       --queue-url \"QUEUE_URL\" \\\n       --redrive-policy '{\"deadLetterTargetArn\":\"DLQ_ARN\",\"maxReceiveCount\":3}'\n   ```\n\n2. **Check message format**:\n   ```bash\n   # Validate message structure\n   aws sqs receive-message \\\n       --queue-url \"QUEUE_URL\" \\\n       --max-number-of-messages 1\n   ```\n\n#### Problem: CloudWatch Logging Issues\n\n**Symptoms**:\n- No logs appearing in CloudWatch\n- \"watchtower\" errors in local logs\n- Missing metrics\n\n**Resolution Steps**:\n1. **Check IAM permissions**:\n   ```bash\n   # Test CloudWatch access\n   aws logs describe-log-groups \\\n       --log-group-name-prefix \"/ai-inference\"\n   \n   aws cloudwatch put-metric-data \\\n       --namespace \"AirGappedRAG\" \\\n       --metric-data MetricName=Test,Value=1\n   ```\n\n2. **Restart worker to reinitialize logging**:\n   ```bash\n   sudo systemctl restart rag-worker\n   ```\n\n3. **Check VPC endpoint connectivity**:\n   ```bash\n   nslookup logs.us-east-1.amazonaws.com\n   curl -I https://logs.us-east-1.amazonaws.com\n   ```\n\n## 📊 Performance Troubleshooting\n\n### High Queue Depth\n\n**Symptoms**: Messages accumulating faster than processing\n\n**Investigation**:\n```bash\n# Check processing rate\naws cloudwatch get-metric-statistics \\\n    --namespace AWS/SQS \\\n    --metric-name NumberOfMessagesDeleted \\\n    --dimensions Name=QueueName,Value=ai-inference-queue-Prod \\\n    --start-time $(date -d '1 hour ago' --iso-8601) \\\n    --end-time $(date --iso-8601) \\\n    --period 300 \\\n    --statistics Sum\n\n# Check inference times\naws cloudwatch get-metric-statistics \\\n    --namespace AirGappedRAG \\\n    --metric-name VLLMResponseTime \\\n    --dimensions Name=Environment,Value=prod \\\n    --start-time $(date -d '1 hour ago' --iso-8601) \\\n    --end-time $(date --iso-8601) \\\n    --period 300 \\\n    --statistics Average,Maximum\n```\n\n**Solutions**:\n1. **Optimize worker polling**:\n   ```bash\n   # Reduce poll interval\n   aws ssm put-parameter \\\n       --name \"/ai-inference/config/Prod/worker-poll-interval\" \\\n       --value \"5\" \\\n       --type String \\\n       --overwrite\n   ```\n\n2. **Scale vLLM resources**:\n   ```bash\n   # Increase GPU memory utilization\n   # Restart vLLM with higher limits\n   ```\n\n3. **Consider horizontal scaling** (future enhancement)\n\n### Memory Issues\n\n**Symptoms**: High memory usage, OOM kills\n\n**Investigation**:\n```bash\n# Check memory usage\nfree -h\nps aux --sort=-%mem | head -10\n\n# Check for memory leaks\nvalgrind --tool=memcheck python src/worker.py\n```\n\n**Solutions**:\n1. **Increase system memory limits**\n2. **Optimize Python memory usage**\n3. **Implement memory monitoring**\n\n## 🔍 Diagnostic Commands\n\n### System Health Check\n```bash\n#!/bin/bash\n# Complete system health check\n\necho \"=== System Health Check ===\"\necho \"Timestamp: $(date)\"\necho\n\necho \"1.
